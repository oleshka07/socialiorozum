# КонтентГров — повна архітектура та логіка продукту
*Згенеровано: 2026-06-18 · Статус: чернетка архітектури · LLM: OpenRouter*

Документ описує **всю логіку** (включно з інтеграціями та автопостингом), розбиту на версії v1 → v2 → v3. Принцип: **інфраструктуру закладаємо повну вже у v1**, а функції вмикаємо поетапно, щоб нічого не переробляти.

---

## 0. Головний принцип UI — «кишка»

Одна довга вертикальна сторінка. Кожен етап пайплайну — це **картка-крок**, складені одна під одною й з'єднані лінією-воронкою. У кожній картці видно:
- вхід (що зайшло в цей крок),
- **редагований промпт** цього кроку + вибір моделі (OpenRouter) + параметри,
- вихід (що крок згенерував),
- кнопки `Запустити` / `Запустити звідси донизу`,
- бейдж `застаріло` (stale), якщо вище щось змінили.

Скоригував промпт → натиснув запуск → крок переписав вихід → усі кроки нижче позначаються як «застарілі» й перераховуються. Уся логіка прозора й редагована на одній сторінці — саме те, що треба, щоб бачити, де що покращувати.

---

## 1. Доменна модель (закладаємо повністю з v1)

Навіть якщо у v1 частина полів не використовується — таблиці й поля створюємо одразу, щоб v2/v3 додавались без міграцій-переробок.

### Сутності

| Сутність | Призначення | Використання |
|---|---|---|
| **Workspace** | акаунт/простір користувача, тримає глобальні налаштування | v1 (один локальний) → v3 (мульти-юзер) |
| **Source** | сирий вхід: транскрипт сесії | v1 |
| **PipelineRun** | один прогін кишки над одним Source | v1 |
| **StepRun** | результат одного кроку в межах прогону | v1 |
| **Idea** | контент-одиниця (ідея), витягнута з транскрипту | v1 |
| **Draft** | чорновий пост, згенерований з ідеї | v1 |
| **ChannelVariant** | варіант поста під конкретний канал (Telegram, IG, FB, Threads) | v1 (тільки TG) → v2 |
| **FinalPost** | фінальний пост після де-AI, готовий до публікації | v1 |
| **ContentPlan** | план розподілу постів у часі | v2 |
| **ScheduleSlot** | дата/час публікації конкретного поста | v2 → v3 (виконання) |
| **Channel** | підключений канал публікації | v3 (у v1/v2 — лише тип, без інтеграції) |
| **PromptTemplate** | версіонований шаблон промпта (глобальний/на крок) | v1 |
| **SettingsBlock** | редаговані блоки: Marketing Context, Tone of Voice, De-AI Rules, Content Strategy | v1 |

### Ключові поля для майбутньої гнучкості (закласти зараз!)

- `Source.origin` = `manual | upload | api` — щоб у v3 додати авто-інжест транскрипцій по API **без зміни схеми**.
- `ChannelVariant.channel_type` з самого початку, навіть якщо значення лише `telegram` — мульти-канал у v2 не ламає модель.
- `PromptTemplate.version` + `scope` (`global | step`) — версіонування промптів і відкат.
- `StepRun.input_hash` + `StepRun.prompt_version` + `StepRun.status` (`fresh | stale | running | error`) — основа каскадної перегенерації.
- `ScheduleSlot` існує у схемі з v1, але активується у v2 — таблиця порожня, код не чіпаємо.

## 2. Повна логіка пайплайну (всі кроки кишки)

Нумерація наскрізна. У дужках — у якій версії крок з'являється на сторінці.

### Крок 0 — Інтейк джерела (v1: ручний · v3: авто по API)
- **v1:** користувач вставляє транскрипт текстом або завантажує файл. Зберігається як `Source`, видно повний транскрибований текст.
- **v3:** сервіс транскрипції шле транскрипт по API/вебхуку → автоматично створюється `Source` (`origin=api`) і автоматично стартує `PipelineRun`.
- Вихід: документ із транскриптом, який можна відкрити й прочитати.

### Крок 1 — Витяг ідей (v1) · *використовує блок Marketing Context*
- Вхід: транскрипт.
- Промпт: «знайди в транскрипті N контент-ідей; для кожної — суть, кут подачі, чому це цінно аудиторії». Промпт тягне **Marketing Context** (що висвітлюємо, яка користь, стилістика, табу).
- Вихід: список `Idea` — видно списком, кожну можна редагувати / вимкнути / додати свою.

### Крок 2 — Перегляд і відбір ідей (v1)
- Користувач бачить ідеї візуально, ставить галочки які брати в роботу. Тут воронка розгалужується: 1 транскрипт → багато ідей.

### Крок 3 — Генерація чорнових постів (v1)
- Вхід: відібрані ідеї.
- Промпт: «з кожної ідеї зроби чорновий пост» (структура, гачок, заклик).
- Вихід: `Draft` на кожну ідею. Видно кожен текст окремо.

### Крок 4 — Tone of Voice (v1) · *використовує блок Tone of Voice*
- Окремий проміжний крок (як ти й хотів). Вхід: чорновики. Промпт переписує текст у голос бренду, тягнучи **Tone of Voice** профіль (приклади постів, лексика, ритм, заборонені звороти).
- Вихід: пости в потрібному голосі.

### Крок 5 — Форматування під канал (v1: Telegram · v2: + IG/FB/Threads)
- Вхід: пости в голосі.
- Промпт під кожен канал (довжина, емодзі, хештеги, розбивка). У v1 активний лише Telegram; решта каналів — картки з позначкою «скоро».
- Вихід: `ChannelVariant` (поки `channel_type=telegram`).

### Крок 6 — Де-AI (v1) · *використовує блок De-AI Rules*
- Вхід: канальні варіанти.
- Промпт прибирає AI-ознаки: типові тире (—), штампи, надмірну симетрію, «as an AI», канцелярит. Тягне редаговані **De-AI Rules**.
- Вихід: `FinalPost` — готовий до копіювання/публікації.

### Крок 7 — Контент-стратегія (v2) · *використовує блок Content Strategy*
- Вхід: фінальні пости + Content Strategy промпт.
- Логіка: вирішує, що з матеріалу зробити 1, 2 чи 3 пости, в якій послідовності, які теми тижня. Працює **перед** плануванням (як ти й казав — спочатку стратегія, потім розкладка).
- Вихід: структурований план тем.

### Крок 8 — Планування / календар (v2)
- Розбиває пости по тижнях/датах. Невеликий календар: або drag-and-drop постів на дати, або система рекомендує дати, а користувач підтверджує.
- Вихід: `ScheduleSlot` на кожен пост.

### Крок 9 — Автопостинг (v3)
- **v1/v2:** користувач копіює фінальний пост і публікує руками.
- **v3:** Telegram-бот публікує за розкладом зі `ScheduleSlot`. Далі — інші канали.

## 3. Логіка стану й перегенерації (серце «прозорості»)

Кожен `StepRun` пам'ятає: який вхід (`input_hash`), який промпт (`prompt_version`), який результат.

Правило каскаду:
1. Користувач редагує промпт кроку K і запускає його.
2. Крок K перегенерує вихід.
3. Усі кроки K+1…N позначаються `stale` (бо їхній вхід змінився).
4. Користувач тисне `Запустити звідси донизу` → кроки перераховуються по черзі.

Це дає саме те, що ти описав: «скоригував промпт — воно відразу переписало текст». І видно lineage — звідки що взялося.

---

## 4. Глобальні редаговані блоки (Settings)

Чотири блоки-промпти, які тягнуться кроками й редагуються в одному місці:
1. **Marketing Context** — про що пишемо, яка користь, для кого, табу. (Крок 1)
2. **Tone of Voice** — приклади постів, лексика, ритм, заборонені звороти. (Крок 4)
3. **De-AI Rules** — список AI-ознак, які прибирати. (Крок 6)
4. **Content Strategy** — правила скільки постів з матеріалу й як розкладати. (Крок 7)

Кожен блок — це `PromptTemplate` зі `scope=global`, версіонований.

## 5. Технологічний стек

| Шар | Вибір | Нотатка |
|---|---|---|
| Frontend | React, одна довга сторінка зі стеком карток-кроків | стан прогону в пам'яті + збереження в БД |
| Backend | API-функції (Node/Edge) | оркеструють кроки, викликають OpenRouter |
| LLM | **OpenRouter** | модель + температура **на кожен крок** окремо |
| БД | Postgres (Supabase) | сутності з §1; Supabase вже у твоєму стеку |
| Файли | сховище транскриптів/завантажень | `Source.origin=upload` |
| Auth | — | додаємо у v3 (мульти-юзер) |

Виклик LLM уніфікований: `runStep(stepRun)` → бере промпт+модель+вхід → OpenRouter → пише вихід і статус. Один інтерфейс на всі кроки.

## 6. Розбивка по версіях

### v1 — Прозора кишка (MVP, та сама логіка, що несе цінність)
Кроки **0(ручний) → 1 → 2 → 3 → 4 → 5(Telegram) → 6**. Результат — готові до копіювання Telegram-пости.
- Ручний інтейк транскрипту (вставити/завантажити).
- Усі промпти редаговані на сторінці, модель через OpenRouter, каскадна перегенерація.
- Зберігання Source / Run / StepRun / FinalPost.
- Публікація — копіювання руками. Календар і автопостинг — кнопки «скоро».
- Інфра під §1 закладена повністю (поля origin, channel_type, schedule-таблиця існують, але неактивні).

### v2 — Стратегія + планування
Додаються кроки **7 (контент-стратегія) → 8 (календар, drag-and-drop / рекомендовані дати)** та форматування **під IG / FB / Threads** (крок 5 розширюється). База збережених постів. Публікація все ще ручна (копіювання з календаря).

### v3 — Інтеграції та автопілот
- Крок 0 авто: інтеграція з сервісом транскрипції по API → авто-створення Source і авто-старт прогону.
- Крок 9: автопостинг у Telegram за розкладом (бот), далі інші канали.
- Мульти-юзер (auth), бібліотека пресетів промптів, базова аналітика.

---

## 7. Що свідомо закладаємо наперед, щоб не переробляти

1. **`Source.origin`** від v1 → авто-інжест по API у v3 без зміни схеми.
2. **`ChannelVariant.channel_type`** від v1 → мульти-канал у v2 безшовно.
3. **`ScheduleSlot`** таблиця існує з v1 (порожня) → планування v2 не вимагає міграції-переробки.
4. **Версіонування `PromptTemplate`** → відкат і A/B промптів пізніше.
5. **`StepRun` lineage + статуси** → каскадна перегенерація вже у v1, нові кроки v2/v3 просто стають у кінець ланцюга.
6. **Уніфікований `runStep`** → додати новий крок = додати конфіг кроку, не новий код інтеграції.

---

## 8. Відкриті питання до старту v1
- Який ліміт ідей з одного транскрипту за замовчуванням (5? 10?).
- Tone of Voice: зібрати 5–10 прикладів «гарних» постів першого коуча.
- Які моделі OpenRouter ставимо дефолтом на кроки витягу ідей / TOV / де-AI (різні за вартістю й якістю).
- Формат завантаження транскрипту: txt / docx / просто paste?
