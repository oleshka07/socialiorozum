## 🟡 Ask-first (3)

### `src/pipeline.ts` — delete+insert без транзакції
**Issue:** у кроках `drafts/tone/format/deai/strategy` спершу `DELETE from post ...`, потім цикл `INSERT`. Якщо OpenRouter упаде на 3-му з 6 постів — стара стадія вже видалена, нова неповна. Run лишається в неузгодженому стані.
**Option A:** обгорнути кожен крок у транзакцію (`BEGIN; delete; insert...; COMMIT`) через виділений `pool.connect()` клієнт — все або нічого.
**Option B:** писати в нову «версію» (insert з новим `step_run`-id), а старе чистити лише після успіху — складніше, дає історію.
**Recommendation:** A. Просто, безпечно, ~0.5 дня. B лишити на потім, якщо знадобиться історія прогонів.

### `src/pipeline.ts` / `server.ts` — подвійний запуск кроку
**Issue:** два кліки «Запустити» (або дві вкладки) на одному run запускають `executeStep` паралельно: обидва `DELETE` + `INSERT` → дублі/гонка.
**Option A:** Postgres advisory lock на `hash(runId+stepKey)` на час кроку; другий виклик одразу 409.
**Option B:** статус-guard: на старту виставляти `step_run.status='running'` умовно (`WHERE status<>'running'`), другий виклик бачить зайнято.
**Recommendation:** B як мінімум (дешево, в одному запиті), A якщо буде кілька воркерів.

### OpenRouter retry-політика
**Issue:** зараз 0 ретраїв — будь-який 429/5xx валить крок.
**Option A:** 2-3 ретраї з експоненційним backoff+jitter лише на 429/5xx/timeout.
**Option B:** без ретраїв, лишити користувачу кнопку «перезапустити крок».
**Recommendation:** A для 429/5xx (вони транзієнтні), але не для 4xx-валідації. ~0.25 дня.

## 🔴 Flag — no fix without context (3)

### Відкритий API над PII — `src/server.ts`
**Issue:** `cors origin:true`, жодної авторизації. Будь-хто з URL читає чужі транскрипти (зміст коучингових сесій = чутливі персональні дані) і палить твій OpenRouter-бюджет.
**Why I can't fix it:** залежить від моделі продукту — один інстанс на коуча (тоді досить басік-аут/VPN) чи мульти-юзер (тоді повноцінний auth + привʼязка `source/run` до власника).
**What needs to happen:** Олег вирішує модель доступу. Мінімум до зовнішнього запуску — будь-яка авторизація + перевірка власника на `GET /api/runs/:id`.

### Транскрипти йдуть у третю сторону (OpenRouter) — політика даних
**Issue:** повний текст сесії відправляється в OpenRouter (далі — до провайдера моделі). Для даних клієнтів коуча це питання згоди й приватності, не лише техніки.
**Why I can't fix it:** юридично-продуктове рішення, не код.
**What needs to happen:** визначити: чи є згода клієнтів коуча; який провайдер/модель прийнятні; retention транскрипту (пропозиція — видаляти `source.transcript` після успішного прогону, лишати лише пости).

### Recovery «застряглого» `running` — `step_run`
**Issue:** якщо процес/контейнер падає під час кроку, статус лишається `running` назавжди; UI не дасть перезапустити коректно.
**Why I can't fix it:** треба домовитись про механізм (TTL на `running` / heartbeat / «розблокувати» при старті).
**What needs to happen:** проста політика: при запуску кроку, якщо попередній `running` старший за N хв — вважати мертвим і дозволити перезапуск.
