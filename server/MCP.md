# 🔌 socialio як інструмент Claude (MCP)

Підключення кабінету до Claude **без API-ключа й без оплати за токени**: думає той Claude, за
якого вже сплачено підпискою (claude.ai, застосунок, Claude Code), а socialio дає йому руки -
прочитати бренд, покласти чернетку, опублікувати, запланувати.

**Головне економічне наслідство:** коли текст пише Claude у чаті, наш AI не працює взагалі -
жодного виклику до OpenAI/Gemini. Єдиний інструмент, що витрачає кредити кабінету, -
`generate_posts` (це написано в його описі, тож модель бере його лише коли просять прямо).

## Як підключити

1. Кабінет → **Інструменти** → «🔌 Підключення до Claude (MCP)» → **Створити адресу** → Копіювати.
2. **claude.ai / застосунок Claude:** Settings → Connectors → **Add custom connector** → вставити
   адресу → Add. У чаті увімкнути конектор `socialio` в меню інструментів.
3. **Claude Code:** `claude mcp add --transport http socialio <адреса>`.
4. Перевірка: «покажи мої чернетки».

Робочий сценарій, під який усе зроблено:

> «візьми голос мого бренду і напиши 3 пости про запуск, збережи чернетками»
> «опублікуй #a1b2c3d4 в telegram»  ·  «заплануй на завтра 9:00»  ·  «що вийшло за місяць?»

## Карусель (кілька фото в одному пості)

Пост може мати до **10 кадрів** (межа Instagram і Telegram; Threads і LinkedIn приймають до 20, але пост
іде в усі мережі одразу). Кожна мережа отримує карусель у своїй формі:

| Мережа | Як публікується |
|---|---|
| Instagram | контейнер на кожен кадр (`is_carousel_item`) → контейнер `CAROUSEL` з `children` і підписом → `media_publish` |
| Threads | контейнери `IMAGE` з `is_carousel_item` → контейнер `CAROUSEL` → `threads_publish` (у режимі гілки карусель - у першому пості) |
| Facebook | кожне фото `published=false` → один допис стрічки з `attached_media[i]` (галерея) |
| Telegram | `sendMediaGroup` (альбом); підпис на першому кадрі, довший за 1024 - окремим повідомленням під альбомом |
| LinkedIn | кожне фото через Images API → пост з `content.multiImage.images` |

**Модель:** обкладинка лишається в `post.media_id` (її знають редактор фото, прев'ю, картка, бот, Mini App),
кадри 2..N - у таблиці `post_slide`. Змінюється список лише через `setPostMediaOrder` (`src/slides.ts`):
вона тримає обидві половини узгодженими й прибирає похідні файли (кропи, зібрані кадри), які ніде більше
не стоять. Кадр каруселі рахується «в ужитку» так само, як обкладинка: без цього проста перестановка
обкладинки на друге місце стирала б цей кадр (спіймано мутаційним тестом).

**Кадри зі сценарію** (`render_carousel`, `src/carousel.ts`): формат «Карусель» пише текст рядками
«Слайд N: …» - раніше весь цей сценарій ішов ПІДПИСОМ під одним фото. Збирач малює кожен слайд картинкою
(sharp + SVG, без моделі): перший рядок - заголовок, решта - текст, `**жирне**` - акцентним кольором,
лічильник `2/8`, нік бренду (@Instagram → @Threads → @канал Telegram → назва бренду; пошту на кадр не
ставимо). Текст ніколи не вилазить за край: шрифт зменшується, задовге слово ріжеться, простирадло
обрізається з «…», і інструмент каже, на яких кадрах. Після збирання текст поста стає підписом (з рядка
«Підпис:», інакше обіцянка + заклик), сценарій - у `post.slides_text`, звідки кадри можна перезібрати.

## Відео-пост (власне відео автора)

Відео стоїть у пості **саме** (фото поруч не буває: Facebook-галерея й LinkedIn відео не беруть) -
`attach_media` з одним id відео, у кабінеті «🎬 Відео», у Mini App «🎬 Відео», у боті - відео у
відповідь на «Фото, альбом чи відео». Текст поста - підпис.

| Мережа | Як публікується | Межа (перевіряється ДО виклику) |
|---|---|---|
| Instagram | контейнер `REELS` з `video_url`, `share_to_feed=true` → чекаємо `FINISHED` (до 5 хв) → `media_publish` | 3 с - 15 хв |
| Facebook | `/{page}/videos` з `file_url` (Meta тягне файл сама); лінк `facebook.com/watch/?v=<id>` | - |
| Threads | контейнер `VIDEO` з `video_url` → чекаємо (до 5 хв) → `threads_publish`; у гілці відео - в першому пості | до 5 хв |
| Telegram | `sendVideo`: до 20 МБ - адресою (Telegram тягне сам), до 50 МБ - файлом від бота (multipart) | до 50 МБ (межа Bot API) |
| LinkedIn | Videos API: `initializeUpload` → PUT частин за межами байтів LinkedIn (ETag) → `finalizeUpload` → чекаємо `AVAILABLE` → пост із `urn:li:video` | 3 с - 30 хв |

YouTube Shorts і TikTok - через наявну кнопку 📤 рілса (ПРО): власне відео поста йде туди тим самим
шляхом, що й зібраний рілс, а підпис - сам текст поста (без моделі).

**Метадані:** `media_asset.duration/width/height` міряє `ffprobe` при збереженні - так, як відео
**показується** (телефон пише вертикальне відео горизонтальним із поміткою «повернути на 90°»).
Мініатюра відео (`/thumb/…`) - кадр із ролика (`ffmpeg`, 1-ша секунда). Файл, який байтами схожий на
відео, але `ffprobe` його не читає, відбивається одразу («пошкоджений чи обрізаний»), а не падає через
кілька хвилин обробки в мережі. Без `ffmpeg` (локально) відео просто без мініатюри й тривалості.

## Сторіс (Instagram і Facebook)

Пост формату `story` публікується **кадр за кадром** - кожен кадр окремою сторіс, без підпису (у
сторіс його нема, тож думка має бути на кадрах), живе 24 год. Кадри - фото (кроп 9:16, 1080×1920) і
відео **разом** (у звичайному пості відео завжди саме, у сторіс - ні), до 10.

| Мережа | Як публікується | Межа |
|---|---|---|
| Instagram | на кадр - контейнер `STORIES` з `image_url` (JPEG 9:16, без кропу до 4:5) або `video_url` → `FINISHED` → `media_publish` | відео до 60 с (перевірка ДО виклику) |
| Facebook | фото - `/{page}/photos` з `published=false` → `/{page}/photo_stories` з `photo_id`; відео - `/{page}/video_stories` `start` → POST на `upload_url` (**лише хост rupload.facebook.com**, заголовки `Authorization: OAuth <токен>` і `file_url`) → чекаємо `uploading_phase=complete` → `finish` | - |
| Telegram, Threads, LinkedIn | сторіс через API не приймають - чесна відмова «зніми мережу з поста», жодного запиту | - |

Адресу завантаження відео приносить відповідь API, тож токен Сторінки йде туди ЛИШЕ якщо це
`https://rupload.facebook.com` - інакше публікація зупиняється. Частковий збій (частина кадрів уже в
мережі): рядок публікації фіксується як надісланий зі списком id, людина бачить «опубліковано k з N,
далі збій: …» - повтор НЕ дублює вже опубліковані кадри (решту додають окремою сторіс). Кадри з
тексту: рядки «Кадр 1: …» → `render_carousel`/«🎨 Зібрати кадри» малює 9:16 у безпечній зоні (без
верхніх 16% під смужками прогресу й нижніх 22% під полем відповіді), без лічильника й «→» - їх малює
сама мережа. Стікери (опитування, посилання) через API не ставляться.

## Заливка частинами (`src/chunks.ts`)

Відео з телефона важить сотні МБ, а nginx пропускає до 20 МБ за запит - тож великі файли ріжуться на
шматки й дописуються на сервері: `PUT /api/media/chunk` (кабінет), `PUT /api/tg/chunk` (Mini App),
`POST /mcp/upload/:token/chunk` (разове посилання). Параметри `?uid=&size=&offset=`, тіло - сирі байти
шматка (`application/octet-stream`, до 16 МБ), імʼя файлу - заголовок `X-File-Name` (браузер шле
percent-encoding, curl - сирі UTF-8; приймаються обидва). **Стан - на диску** (`media/tmp/<ключ>.part` +
`.json`), тож деплой посеред заливки нічого не губить. Повтор уже записаного шматка пропускається,
«дірка» → `409` з `received` (продовжуй звідти), повтор ОСТАННЬОГО шматка після обриву вертає той самий
результат. Межі: файл до `UPLOAD_MAX_MB` (типово 500), до 6 незавершених заливок на кабінет/посилання,
на диску завжди лишається ≥3 ГБ. Недолите старше доби прибирає `lifecycle`. Зібраний файл дедуплікується
так само, як звичайна заливка (sha256 вмісту в `external_id`).

## Фото й відео з комп'ютера (`media_upload_link`)

Передати файл у конектор через модель неможливо: єдиний канал - текстові аргументи, а фото текстом -
це мільйони символів у контексті. Тому інструмент видає **разове посилання**
`/mcp/upload/<48 hex>`, і файли йдуть напряму з комп'ютера на сервер:

- **Є термінал** (Claude Code, Cowork, Git Bash): у відповіді готова команда -
  `curl -fsS "<посилання>/sh" -o socialio-upload.sh && sh socialio-upload.sh "<папка>"`. Вона качає
  короткий POSIX-скрипт (його можна прочитати перед запуском: він лише читає файли з указаної папки й
  шле їх на це посилання) і запускає через `sh` - однаково в bash, dash, zsh і BusyBox. Скрипт бере фото
  й відео з кореня папки (`find`, а не глоб: у zsh глоб, що нічого не знайшов, валить усю команду), ріже
  великі на шматки по 15 МБ і сам повторює обірваний шматок. Відповідь - **рядок на файл**
  (`✓ збережено`, `= уже в медіатеці`, `✗ причина`), бо це читає Claude. Для PowerShell лишилась
  команда одним запитом (лише фото до 20 МБ).
- **Терміналу нема:** те саме посилання в браузері відкриває сторінку, куди фото й відео
  перетягуються (шле частинами по 8 МБ, з відсотками).
- Далі - `list_media` з `unused_only: true` (для відео - `kind: "video"`) → `attach_media`.
- ⚠️ **Cowork** працює в пісочниці: якщо мережевий доступ до домену socialio там закритий, curl не
  достукається - тоді посилання віддається людині в браузер.

Межі посилання: **лише додає** файли в медіатеку одного кабінету (нічого не читає й не показує, крім
назви кабінету на сторінці), живе 5-180 хв (типово 60), до 200 файлів і **5 ГБ** (`upload_link.bytes_left`:
відео по 500 МБ інакше дозволили б одним посиланням забити диск). Тип визначається за байтами: текст
під `.png` відбивається з людською причиною. Місце на посиланні забирається атомарно (паралельний
скрипт не проскочить ліміт), а відбитий файл чи дубль місця не зʼїдає. **Повтор тієї самої папки
копій не плодить:** відбиток вмісту (sha256 оригінальних байтів) лягає в `media_asset.external_id`, і
так само дедуплікує звичайна заливка в кабінеті - посилання й кабінет впізнають файли одне одного.
Протухлі посилання стирає `lifecycle` через добу. Код: `src/uploadlink.ts` + роути
`GET/POST /mcp/upload/:token`, `POST …/chunk`, `GET …/sh` у `server.ts` (під `/mcp/`, тож PIN бети їх
пропускає), таблиця `upload_link`. Юніти: `test/uploadlink.test.mjs` (скрипт там реально запускають у
bash, dash і zsh з підробленим curl, що говорить протоколом шматків, - з обривом і «продовжуй з N»).

## Безпека

- **Адреса = пароль від кабінету.** Вона одна на людину (відкриває всі її кабінети) і дає ті самі
  права, що й вхід у кабінет (крім налаштувань і видалення). Не публікувати, не вставляти в чужі чати.
- Засвітилась - «🔄 Перевипустити адресу»: стара мре **одразу**, у Claude конектор додається заново.
- «Відключити» прибирає адресу зовсім; кабінет лишається як є.
- Токен - 32 байти з `crypto.randomBytes`; формат (64 hex) перевіряється **до** запиту в БД.
- Кожен токен бачить **лише свій** воркспейс (перевірено на двох акаунтах).
- Рейт-ліміт 240 запитів/хв на IP.

## Технічні деталі (для тих, хто чинитиме)

- Код: `server/src/mcp.ts` (протокол + інструменти), роути в `server/src/server.ts`
  (`/mcp`, `/mcp/:token`, `/api/integrations/mcp*`), юніти `server/test/mcp.test.mjs`.
- **Транспорт:** Streamable HTTP - один `POST` з тілом JSON-RPC 2.0. Відповідь JSON; SSE лише
  якщо клієнт JSON не приймає. `GET` віддає **405** (потік «сервер→клієнт» не потрібен -
  специфікація дозволяє його не підтримувати), `DELETE` - 204.
- **Версії протоколу:** `2025-06-18`, `2025-03-26`, `2024-11-05` (відому клієнтську ехо-відповіддю,
  невідому зводимо до найновішої своєї). Батч-запити 2025-03-26 підтримані.
- **Автентифікація:** токен у шляху `/mcp/<64 hex>`, бо у формі «Custom connector» на claude.ai
  місця під заголовок немає. Також приймаються `Authorization: Bearer`, `X-Socialio-Token`
  і `?token=`. Токен живе в таблиці `mcp_token` (належить людині, а не кабінету; там же активний
  кабінет конектора й остання активність).
- **Нових env немає.** На беті роути звільнені від PIN-гейта (у конекторі PIN ввести
  ніде, а захист там інший - токен).
- Помилки інструментів повертаються всередині результату (`isError`), а не як помилки протоколу:
  Claude бачить причину й виправляється сам, замість того щоб рвати зʼєднання.
- Матеріали й пости з чату мають `source.origin='mcp'` (мітка «🔌 З Claude» у стрічці й на картці)
  і потрапляють у режим «з власних слів автора» при переробці - щоб правка не дописувала генерику.

## Якщо не працює

| Симптом | Причина й що робити |
|---|---|
| `401` у Claude | адреса стара або обрізана - скопіюй заново з кабінету |
| Конектор додався, інструментів нема | увімкни `socialio` в меню інструментів у самому чаті |
| `405` при перевірці в браузері | це нормально: браузер робить `GET`, MCP говорить `POST` |
| Пост не публікується | мережа не підключена в кабінеті (`workspace_info` покаже підключені) |
| Claude вигадує факти | дай матеріал: `add_material`, далі «напиши пост із матеріалу #id» |

## Перевірити руками (без Claude)

```bash
curl -s -X POST "<адреса>" -H 'content-type: application/json' -H 'accept: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 300
```
